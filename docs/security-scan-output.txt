Trivy was never available in the local build sandbox (no `trivy` CLI, no
running Docker daemon there), so every scan result documented here is real
GitHub Actions CI output from the actual pushed repository - not fabricated,
and not run locally. Screenshots of the actual runs are in
docs/screenshots/: security-scan-run3-failed.png (run 3, the real
CRITICAL/HIGH findings below) and repo-after-fix.png (repo state after the
fix landed).

=== RUN 1: security-scan job failed to start ===
Commit 843c9eb (run 32900480446)
Error: Unable to resolve action `aquasecurity/trivy-action@0.24.0`,
unable to find version `0.24.0`
Cause: trivy-action's git tags are v-prefixed (v0.24.0, v0.30.0, ...); the
workflow referenced the tag without the `v`, so it didn't resolve at all.
Fix: commit 9498d0a, pinned to `aquasecurity/trivy-action@v0.30.0`.

=== RUN 2: security-scan job failed to start (different action) ===
Commit 9498d0a
Error: Unable to resolve action `aquasecurity/setup-trivy@v0.2.2`,
unable to find version `v0.2.2`
Cause: trivy-action@v0.30.0 pins a nested `aquasecurity/setup-trivy@v0.2.2`
dependency that Aqua Security has since deleted from that repo's tags.
Fix: commit 937ab67, bumped to `aquasecurity/trivy-action@v0.36.0`.

=== RUN 3: security-scan job ran and correctly failed the build ===
Commit 937ab67 (run 32902790201, job 97981508869)
Screenshot: docs/screenshots/security-scan-run3-failed.png
Trivy actually executed this time and found real findings in the built
image (henkel-assessment-app:937ab674c1ad4934caedf3513b96aa0abf4dee91):

  alpine 3.23.4 (OS packages)
    HIGH  CVE-2026-45447  libcrypto3 / libssl3  3.5.6-r0 -> fixed 3.5.7-r0
          openssl: Heap Use-After-Free in OpenSSL PKCS7_verify()

  Node.js (node-pkg) - 19 findings, 1 CRITICAL + 18 HIGH, e.g.:
    CRITICAL  CVE-2026-59873  tar 6.2.1 -> 7.5.19 (DoS via gzip bomb)
    HIGH      7 more tar CVEs, brace-expansion (3), cross-spawn,
              glob, ip-address, minimatch (3), sigstore

  `Total: 2 (HIGH: 2, CRITICAL: 0)` for the OS layer,
  `Total: 19 (HIGH: 18, CRITICAL: 1)` for Node.js -> exit code 1, build failed.

Root cause: every one of the 19 Node.js findings was inside npm's/yarn's
own vendored dependencies under /usr/local/lib/node_modules/npm/... and
/opt/yarn-v1.22.22/..., which the node:20-alpine base image bundles for
build-time convenience. The app's own app/node_modules/* (express,
body-parser, etc.) all reported 0 vulnerabilities in the same scan - this
was never an application vulnerability.

Fix: commit 5a8acd2 -
  1. `RUN apk upgrade --no-cache` in the Dockerfile's runtime stage, to
     pick up the already-published openssl fix.
  2. Deleted npm, npx, corepack, and yarn from the runtime image - the app
     only ever executes `node server.js`, so none of that tooling (or its
     vulnerabilities) needs to ship in the final image at all.

=== TAKEAWAY ===
This is the real, unedited debugging path for this pipeline: two broken
action version pins, one genuine security finding traced to unnecessary
base-image tooling rather than the app, all found and fixed via actual CI
runs against the actual pushed repository - not simulated locally.
